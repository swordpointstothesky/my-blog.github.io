## 前言

在上一篇博客中，我们完成了用户管理 CRUD 功能的开发，系统在本地已经跑通了。但本地跑通只是开始，**真正的价值在于让系统跑在公网上，让任何人可以访问**。

部署不仅是技术能力的体现，更是产品交付的起点。这篇文章记录了我将通用后台管理系统部署到生产环境的全过程，包括：

- **Supabase**：免费 PostgreSQL 云数据库
- **Railway**：Docker 容器化部署 .NET 10 后端
- **Vercel**：自动化部署 React 前端

全程零成本，适合个人项目和技术作品展示。

---

## 一、部署方案设计

在选型时，我考虑了三个核心需求：

| 需求 | 选择 | 理由 |
| :--- | :--- | :--- |
| 数据库 | Supabase | 提供免费 PostgreSQL，500MB 存储，支持连接池 |
| 后端 | Railway | 支持 Docker 部署，每月 $5 免费额度，无需绑卡 |
| 前端 | Vercel | GitHub 集成自动部署，免费 SSL，全球 CDN |

**为什么不用 Render？** Render 虽然也支持免费部署，但需要绑定信用卡验证身份，对于没有国外信用卡的开发者不太友好。Railway 同样提供免费额度且无需绑卡，对个人开发者更友好。

## 二、数据库部署：Supabase

### 2.1 创建项目

1. 访问 [Supabase](https://supabase.com)，用 GitHub 账号登录
2. 点击 **New Project**，填写项目名称和数据库密码
3. 选择区域（推荐选择靠近目标用户的区域）
4. 等待项目初始化完成（约 2-3 分钟）

### 2.2 获取连接字符串

在项目 Dashboard 中，点击右上角的 **Connect** 按钮：

1. 选择 **Direct** 选项卡
2. 选择 **Session Pooler** 连接类型（对 .NET 应用更友好）
3. 复制连接字符串，格式如下：

在appsettings.json中添加

```json
"ConnectionStrings": {
  "DefaultConnection": "Host=aws-0-us-east-1.pooler.supabase.com;Port=5432;Database=postgres;Username=postgres.eiizizuejfhvfssurtxh;Password=Hongxin152@;SSL Mode=Require;Trust Server Certificate=true"
}
```

> **注意**：`[YOUR-PASSWORD]` 需要替换为创建项目时设置的数据库密码。Supabase **不会再次显示** 密码，如果忘记需要重置。

### 2.3 重置数据库密码（如果忘记）

1. 进入项目 **Settings → Database**
2. 在 Database Password 区域点击 **Reset database password**
3. 设置新密码并保存

> **⚠️ 重要**：重置密码会立即断开所有现有连接，需要在所有使用该数据库的应用中更新密码。

## 三、后端部署：Railway

### 3.1 准备 Dockerfile

Railway 支持直接部署 Docker 容器。在项目根目录创建 `Dockerfile`：

```dockerfile
# 构建阶段
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /app

# 复制并还原依赖
COPY backend/*.csproj ./backend/
RUN dotnet restore ./backend/GeneralAdmin.Backend.csproj

# 发布应用
COPY backend/. ./backend/
RUN dotnet publish ./backend/GeneralAdmin.Backend.csproj -c Release -o out

# 运行阶段
FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app
COPY --from=build /app/out .

ENV ASPNETCORE_URLS=http://+:8080
EXPOSE 8080

ENTRYPOINT ["dotnet", "GeneralAdmin.Backend.dll"]
```

关键点说明：

使用 mcr.microsoft.com/dotnet/aspnet:10.0 作为运行时镜像，与项目目标框架匹配

设置 ASPNETCORE_URLS=http://+:8080，确保应用监听 Railway 分配的端口

程序集名称必须与项目输出一致

### 3.2 在 Railway 部署

1.访问 Railway，用 GitHub 登录

2.点击 New Project → Deploy from GitHub repo

3.选择你的 GitHub 仓库

4.Railway 会自动检测 Dockerfile 并开始构建

### 3.3 配置环境变量

部署成功后，进入服务页面：

1.点击 Variables 选项卡

2.添加环境变量：

| Key | Value |
| :--- | :--- |
| ConnectionStrings__DefaultConnection | Supabase 连接字符串 |

⚠️ 踩坑提醒：在 .NET 中，环境变量名必须使用双下划线 __ 作为层级分隔符，例如 ConnectionStrings__DefaultConnection，而不是 ConnectionStrings.DefaultConnection 或 ConnectionStrings_DefaultConnection。

.NET 的 IConfiguration 会自动将 ConnectionStrings__DefaultConnection 映射为 ConnectionStrings:DefaultConnection 的配置键。

### 3.4 启用公网访问

进入 Settings → Networking

点击 Generate Domain

Railway 会生成 xxxx.up.railway.app 格式的域名

## 四、前端部署：Vercel

### 4.1 配置环境变量

在 frontend 目录下创建 .env.production：

```env
VITE_API_BASE_URL=https://你的后端域名.up.railway.app
```

| 注意：Vite 只暴露以 VITE_ 开头的环境变量给客户端。

### 4.2 创建 API 客户端

为了让前端在生产环境使用正确的后端地址，需要配置 Axios 的 baseURL：

```ts
// src/api.ts
import axios from 'axios';

const api = axios.create({
    baseURL: import.meta.env.VITE_API_BASE_URL || '',
});

export default api;
```

然后所有组件中的 axios 替换为 api 实例。

### 4.3 在 Vercel 部署

访问 Vercel，用 GitHub 登录

点击 Add New → Project

导入 GitHub 仓库

Root Directory 设置为 frontend

在 Environment Variables 中添加 VITE_API_BASE_URL

点击 Deploy

### 4.4 解决 SPA 路由 404 问题

部署完成后，直接访问 /login 或 /users 路径会返回 404。这是因为 Vercel 默认将每个路由当作静态文件处理，找不到对应的 login.html 就会报 404。

解决方案：在 frontend 目录下创建 vercel.json：

```json
{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

这样所有请求都会被重定向到 index.html，由 React Router 接管路由。

## 六、踩坑记录（最有价值的部分）

### 坑 1：环境变量名格式错误

现象：部署后日志显示 Failed to connect to localhost:5432。

原因：环境变量名写成了 ConnectionStrings_DefaultConnection（单下划线），.NET 无法识别。

解决：改为 ConnectionStrings__DefaultConnection（双下划线）。

.NET 配置系统使用双下划线作为层级分隔符：

ConnectionStrings__DefaultConnection → ConnectionStrings:DefaultConnection

ConnectionStrings.DefaultConnection → 在环境变量中不生效

### 坑 2：Supabase 密码找不到

现象：连接字符串中的 [YOUR-PASSWORD] 不知道怎么填。

原因：Supabase 在创建项目后不会再次显示密码。

解决：进入 Settings → Database → Reset database password，重置新密码。

### 坑 3：SPA 路由 404

现象：首页能访问，但刷新 /login 或 /users 返回 404。

原因：Vercel 默认把每个路径当作静态文件处理。

解决：添加 vercel.json 配置 rewrites 规则。

### 坑 4：.NET 读取连接字符串方式

```csharp
// ✅ 正确
var connectionString = builder.Configuration.GetConnectionString("DefaultConnection");

// ✅ 也可以
var connectionString = builder.Configuration["ConnectionStrings:DefaultConnection"];

// ❌ 不会生效
var connectionString = builder.Configuration["ConnectionStrings_DefaultConnection"];
```
