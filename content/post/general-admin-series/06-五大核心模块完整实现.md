## 一、文件上传

### 1.1 后端设计

**核心接口**：

```csharp
[HttpPost("upload-image")]
public async Task<IActionResult> UploadImage(IFormFile file) { ... }

[HttpPost("upload")]
public async Task<IActionResult> Upload(IFormFile file) { ... }
```

**关键设计点**：

| 设计点 | 方案 |
| :--- | :--- |
| **文件存储** | 本地 `wwwroot/uploads/2026/09/30/`，按日期分目录 |
| **文件名** | `{Guid:N}{ext}`，防止重名和路径穿越 |
| **类型校验** | 白名单（图片：jpg/png/gif/webp；文件：pdf/doc/zip 等）|
| **大小限制** | 图片 5MB，文件 20MB |
| **静态访问** | `app.UseStaticFiles()` 让 `/uploads/xxx.jpg` 可访问 |

**核心代码**：

```csharp
private async Task<IActionResult> UploadFileInternal(
    IFormFile file, string[] allowedExtensions, long maxSize)
{
    if (file == null || file.Length == 0)
        return BadRequest(new { message = "请选择要上传的文件" });

    if (file.Length > maxSize)
        return BadRequest(new { message = $"文件大小不能超过 {maxSize / 1024 / 1024}MB" });

    var ext = Path.GetExtension(file.FileName).ToLowerInvariant();
    if (!allowedExtensions.Contains(ext))
        return BadRequest(new { message = $"不支持的文件类型：{ext}" });

    // 防路径穿越 + 防重名
    var fileName = $"{Guid.NewGuid():N}{ext}";
    var dateFolder = DateTime.Now.ToString("yyyy/MM/dd");
    var relativePath = $"uploads/{dateFolder}/{fileName}";

    var webRoot = _env.WebRootPath ?? Path.Combine(Directory.GetCurrentDirectory(), "wwwroot");
    var uploadDir = Path.Combine(webRoot, "uploads", dateFolder);
    Directory.CreateDirectory(uploadDir);

    await using (var stream = new FileStream(Path.Combine(uploadDir, fileName), FileMode.Create))
    {
        await file.CopyToAsync(stream);
    }

    return Ok(new { url = $"/{relativePath}", fileName = file.FileName, size = file.Length });
}
```

### 1.3 踩坑记录

**坑 1：Vite 代理漏了 `/uploads`**

上传后图片不显示，F12 看请求 404。原因：`vite.config.ts` 只代理了 `/api`，`/uploads` 走了前端服务器。

**修复**：

```ts
server: {
    proxy: {
        '/api': { target: 'https://localhost:7220', changeOrigin: true, secure: false },
        '/uploads': { target: 'https://localhost:7220', changeOrigin: true, secure: false },
    }
}
```

**坑 2：头像更新后 Header 不刷新**

`Layout` 只在挂载时请求一次头像。用户上传后，右上角头像不变。

**方案**：用**自定义事件**通知 Layout：

```tsx
// Profile.tsx 上传成功后
window.dispatchEvent(new CustomEvent('avatar-updated', { detail: url }));

// Layout.tsx 监听
window.addEventListener('avatar-updated', (e: any) => {
    setAvatar(e.detail);
});
```

## 二、参数校验

### 2.1 DTO 加校验特性

```csharp
public class CreateStudentRequest
{
    [Required(ErrorMessage = "姓名不能为空")]
    [MaxLength(50, ErrorMessage = "姓名不能超过 50 个字符")]
    public string Name { get; set; } = string.Empty;

    [Required(ErrorMessage = "性别不能为空")]
    public string Gender { get; set; } = string.Empty;

    [Range(1, 200, ErrorMessage = "年龄必须在 1-200 之间")]
    public int Age { get; set; }

    [EmailAddress(ErrorMessage = "邮箱格式不正确")]
    public string? Email { get; set; }
}
```

### 2.2 统一错误响应

**`ValidationFilter`**（全局过滤器）：

```csharp
public class ValidationFilter : IActionFilter
{
    public void OnActionExecuting(ActionExecutingContext context)
    {
        if (!context.ModelState.IsValid)
        {
            var errors = context.ModelState
                .Where(kv => kv.Value?.Errors.Count > 0)
                .SelectMany(kv => kv.Value!.Errors.Select(e => e.ErrorMessage))
                .ToList();

            context.Result = new BadRequestObjectResult(new
            {
                code = 400,
                message = errors.FirstOrDefault() ?? "参数校验失败",
                errors,
            });
        }
    }

    public void OnActionExecuted(ActionExecutedContext context) { }
}
```

**`Program.cs` 注册**：

```csharp
builder.Services.AddControllers(options =>
{
    options.Filters.Add<ValidationFilter>();
});

// ⚠️ 关键：关闭默认 ModelState 响应，避免格式冲突
builder.Services.Configure<ApiBehaviorOptions>(options =>
{
    options.SuppressModelStateInvalidFilter = true;
});
```

### 2.3 前后端双重校验

| 层级 | 目的 | 例子 |
| :--- | :--- | :--- |
| **前端** | 体验优化（即时提示） | `validate()` 检查必填项 |
| **后端** | 安全兜底（防止绕过） | `[Required]` 特性 + ModelState |

**面试金句**：

> "前端校验是**体验**，后端校验是**安全**。前端可以绕过，后端必须兜底。"

这是最复杂的一个模块，涉及 **SignalR 实时通讯**。

### 5.1 数据库设计

```

    ↓ 一对多

    ↓ 一对多
Messages（消息）
```

**核心字段**：

| 表 | 关键字段 |
| :--- | :--- |
| `Conversations` | `Type`（single/group）、`LastMessageContent`、`LastMessageTime` |
| `ConversationMembers` | `LastReadMessageId`（未读计数用）|
| `Messages` | `ContentType`（text/image/file）、`FileUrl`、`FileName` |

### 5.2 SignalR Hub

**`ChatHub`**：

```csharp
[Authorize]
public class ChatHub : Hub
{
    public override async Task OnConnectedAsync()
    {
        var userId = GetUserId();
        // 把自己加入所有会话的组
        var conversationIds = await _chatService.GetUserConversationIdsAsync(userId);
        foreach (var convId in conversationIds)
        {
            await Groups.AddToGroupAsync(Context.ConnectionId, $"conv_{convId}");
        }
    }

    public async Task<MessageDto> SendMessage(SendMessageRequest request)
    {
        var message = await _chatService.SendMessageAsync(GetUserId(), request);
        // 广播给会话内所有在线用户
        await Clients.Group($"conv_{request.ConversationId}")
            .SendAsync("ReceiveMessage", message);
        return message;
    }

    public async Task Typing(long conversationId)
    {
        await Clients.OthersInGroup($"conv_{conversationId}")
            .SendAsync("UserTyping", new { conversationId, userId = GetUserId() });
    }

    public async Task MarkRead(long conversationId, long lastMessageId)
    {
        await _chatService.MarkReadAsync(GetUserId(), conversationId, lastMessageId);
    }
}
```

### 5.5 踩坑记录

**坑 1：CORS 不能用 `AllowAnyOrigin`**

SignalR 需要 `AllowCredentials`，但不能和 `AllowAnyOrigin` 同时使用。

**修复**：

```csharp
policy.WithOrigins("http://localhost:5173", "https://your-app.vercel.app")
      .AllowAnyMethod()
      .AllowAnyHeader()
      .AllowCredentials();
```

**坑 2：Vite 代理需要 `ws: true`**

```ts
'/hubs': {
    target: 'https://localhost:7220',
    changeOrigin: true,
    secure: false,
    ws: true,   // ← 必须
}
```

**坑 3：设置按钮遮挡发送按钮**

全局悬浮设置按钮（`fixed bottom-6 right-6`）挡住了聊天输入框的发送按钮。

**修复**：给输入框区域加 `pr-20`，避开悬浮按钮。

## 六、RBAC 权限体系补全

在做以上功能时，发现之前的 RBAC 有几个问题：

1. **权限数据不完整**——新增的功能没有对应权限
2. **后端 API 没有细粒度校验**——只用 `[Authorize]`（登录即可）
3. **菜单和按钮没有按权限过滤**

### 6.1 动态权限策略

**`PermissionPolicyProvider`**：

```csharp
public class PermissionPolicyProvider : IAuthorizationPolicyProvider
{
    public Task<AuthorizationPolicy?> GetPolicyAsync(string policyName)
    {
        if (policyName.StartsWith("Permission:"))
        {
            var permission = policyName.Substring("Permission:".Length);
            var policy = new AuthorizationPolicyBuilder()
                .RequireAuthenticatedUser()
                .AddRequirements(new PermissionRequirement(permission))
                .Build();
            return Task.FromResult<AuthorizationPolicy?>(policy);
        }
        return _fallbackProvider.GetPolicyAsync(policyName);
    }
}
```

**`HasPermissionAttribute`**：

```csharp
public class HasPermissionAttribute : AuthorizeAttribute
{
    public HasPermissionAttribute(string permission) : base($"Permission:{permission}") { }
}
```

**Controller 使用**：

```csharp
[HttpGet] [HasPermission("student:view")]
[HttpPost] [HasPermission("student:create")]
[HttpPut("{id}")] [HasPermission("student:edit")]
[HttpDelete("{id}")] [HasPermission("student:delete")]
```

### 6.2 权限数据自动同步

**问题**：手动 SQL 维护权限太麻烦，加新功能要写一堆 SQL。

**方案**：**代码集中定义，程序启动时自动同步**。

**`PermissionDefinitions.cs`**：

```csharp
public static class PermissionDefinitions
{
    public static readonly List<PermissionDefinition> All = new()
    {
        new("user:view", "查看用户", "用户管理"),
        new("user:create", "创建用户", "用户管理"),
        // ... 所有权限
    };
}
```

**`PermissionSeeder`**：

```csharp
public static async Task SeedAsync(AppDbContext db)
{
    var existing = await db.Permissions.ToListAsync();
    var existingNames = existing.Select(p => p.Name).ToHashSet();

    foreach (var def in PermissionDefinitions.All)
    {
        if (!existingNames.Contains(def.Name))
        {
            db.Permissions.Add(new Permission { ... });
        }
    }
    await db.SaveChangesAsync();

    // 自动给 Admin 分配所有权限
    // ...
}
```

**效果**：以后加新权限，**只需改 `PermissionDefinitions.cs`**，重启后端自动同步，**不用写 SQL**。

### 6.3 前端权限控制

**`usePermission` Hook**：

```tsx
export function usePermission() {
    const permissions = useMemo(() => parsePermissionsFromToken(), []);
    const hasPermission = (permission: string) => permissions.includes(permission);
    return { permissions, hasPermission };
}
```

**按钮控制**：

```tsx
{hasPermission('student:create') && (
    <Button onClick={handleOpenCreate}>新增</Button>
)}
```

**菜单过滤**：

```tsx
const menuPermissionMap: Record<string, string> = {
    '/users': 'user:view',
    '/roles': 'role:view',
    '/students': 'student:view',
};

const filterMenus = (menus) => {
    return menus.filter((m) => {
        const required = menuPermissionMap[m.path];
        if (!required) return true;
        return hasPermission(required);
    });
};
```

## 七、踩坑总结

### 坑 1：`SuppressModelStateInvalidFilter` 必须配置

如果没配，.NET 会返回默认的 `ProblemDetails` 格式，前端拿不到 `message`。

### 坑 2：`[Required]` 对非空类型无效

```csharp
[Required]
public int Age { get; set; }   // ❌ int 默认是 0，永远"有值"
```

**正确做法**：用 `[Range]`。

### 坑 3：EF Core 迁移不带默认值

`db.Database.Migrate()` 生成的表**没有 `DEFAULT` 值**，手动 SQL 插入时需要显式提供 `CreateTime`。

### 坑 4：SignalR 重连丢消息

`withAutomaticReconnect` 重连后，**离线期间的消息不会自动推送**，需要手动刷新。

### 坑 5：大文件上传超时

默认 `RequestSizeLimit` 可能不够，需要按接口设置：

```csharp
[RequestSizeLimit(20 * 1024 * 1024)]
```
